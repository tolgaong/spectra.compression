# Support Policy

Issues are prioritized by risk, correctness impact, reliability, affected
usage, blast radius, resource impact, regression severity, and workaround
availability—not by customer tier.

## Public issues

The public issue tracker accepts:

- reproducible bugs;
- compatibility and interoperability reports;
- documentation corrections;
- feature requests with concrete semantics and use cases.

Include the package and version, runtime, operating system, format, API shape,
and a minimal reproduction whenever possible. Remove unrelated application code
and verify that a sample is safe to publish.

Do not disclose secrets, passwords, tokens, personal data, proprietary content,
or private archives in public issues. Follow [SECURITY.md](SECURITY.md) for
security-sensitive reports.

## Compatibility boundaries

Partial format support is not a promise that nearby or historically similar
variants will work. A report about an unsupported shape is still useful when it
includes interoperability evidence, but it may be treated as a feature request
rather than a defect.

This policy does not create a support or response-time SLA.
